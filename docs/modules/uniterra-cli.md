# Module: uniterra-cli

**Purpose:** Public npm installer (`@uniterra-solutions/uniterra`, bin `uniterra`) — one-command desktop app setup and update for macOS and Windows, building the app from the release's source (prebuilt asset when available, else the auto-generated archive) on the user's machine.

Source: `packages/uniterra-cli/src/` (`cli.ts`, `install-logic.ts`); tests `test/pbt.test.mts`.

## Public API

`uniterra` commands:

| Command                               | Flags                                                       | Behavior                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `uniterra setup`                      | `--source <dir>`, `--move-source`, `--no-open`, `--dry-run` | Full install: fetch release (or build a `--source` local checkout) → `pnpm install --frozen-lockfile` → build (skipped when the prebuilt marker is present) → package (`--mac` → `Uniterra.app` / `--win --dir` → `win-unpacked/`) → embed source → install (macOS `~/Applications/Uniterra.app`; Windows `%LOCALAPPDATA%\Programs\Uniterra` + Start Menu shortcut) → launch (unless `--no-open`) |
| `uniterra update`                     | `--source <dir>`, `--move-source`, `--no-open`, `--dry-run` | One-command full update: `npm install -g @uniterra-solutions/uniterra@latest` (CLI self-update, fail fast), then the exact `uniterra setup` build/install flow, then relaunch the app (unless `--no-open`) — the desktop's Update Now quits the app and runs this, so the relaunch is the restart                                                                                                 |
| `uniterra --version` / `-v`           | —                                                           | Print CLI version from `package.json`                                                                                                                                                                                                                                                                                                                                                             |
| `uniterra --help` / `-h` / no command | —                                                           | Print help                                                                                                                                                                                                                                                                                                                                                                                        |

Errors: any thrown error → `uniterra: <message>` on stderr, exit `1` (`cli.ts`).

## Setup / Update Flow

Both commands execute the same stage plan (`installPlan`, PBT-locked); `uniterra update` prepends the CLI self-update stage. `runInstallPlan` (`cli.ts`) dispatches the stages; `buildInstallApp` covers steps 2–14:

1. `update-cli` (`uniterra update` only, runs FIRST — before the long build, so npm/permission problems surface immediately): `npm install -g @uniterra-solutions/uniterra@latest`.
2. Resolve source: `--source <dir>` (validated by `packages/uniterra-desktop/package.json`; version read from that package.json) — or fetch latest release (404 → `releases?per_page=1` fallback), download the prebuilt source asset `uniterra-src-<tag>.tar.gz` when the release carries it (else the auto-generated archive), extract (`/usr/bin/tar` macOS / `tar` from PATH Windows — Win10+ ships bsdtar), locate the `uniterra-*` root.
3. `--dry-run` short-circuits here (the plan is empty): `uniterra update --dry-run` prints the full update plan and stops — no downloads at all (deterministic/offline); `uniterra setup --dry-run` still resolves the source to print its report (no install).
4. Resolve pnpm (`resolvePnpm`): probe `pnpm --version`; if absent, `npx --yes pnpm@<pin>` (the pin comes from the source tree's `packageManager`) — the CLI runs on node, so node+npm/npx are guaranteed and pnpm is self-provisioned.
5. `pnpm install --frozen-lockfile` with `CI: 'true'` (pnpm 11 aborts without a TTY).
6. `pnpm run build` — skipped when `hasPrebuiltSource` is true (the asset ships CI-built dist/lib; old releases and `--source` checkouts build as before).
7. Package: `pnpm exec electron-builder <builderArgs(platform, version)>` in `packages/uniterra-desktop`.
8. `findBuiltApp(platform)`: the `.app` under `dist/mac-*` / the `win-unpacked` dir.
9. Move the artifact out of the tree (embedding the source into itself is illegal): `/bin/mv` (macOS, cross-volume safe) / `fs.rename` with EXDEV fallback to `robocopy` + `rm` (Windows — CI workspaces can live on another volume than the temp dir).
10. Embed source: `/bin/cp -R <src> <app>/Contents/Resources/src` / Windows `embedStrategy` — a downloaded source is a same-volume `fs.rename` (instant, `robocopy /MT:16` fallback); a `--source` checkout is `robocopy`-copied UNLESS `--move-source` opts the disposable checkout into the same move (the Windows CI verification replays the closer-to-real user flow this way) — the tree the packaged app resolves everything from (the pnpm store is hundreds of thousands of small files).
11. Install: `/usr/bin/ditto` → `~/Applications/Uniterra.app` / same-volume `fs.rename` → `%LOCALAPPDATA%\Programs\Uniterra` (tmp and LOCALAPPDATA are both on C:, so the multi-GB move is instant; ANY rename failure — EXDEV cross-volume, EPERM locked files — falls back to `robocopy /MT:16 /R:5 /W:5`), replacing any existing copy. Windows then re-points every pnpm junction whose absolute target still names the staging tree (`repointJunctions` → `remapJunctionTarget`), re-rooting it onto the FINAL installed source dir — the same-volume renames that embedded and installed the source preserved those reparse points verbatim.
12. Windows only: Start Menu shortcut via `powershell` WScript.Shell (best-effort — a missing shortcut never fails the install).
13. `launch-app` (unless `--no-open`): `/usr/bin/open` / detached spawn of `Uniterra.exe` — after an update this relaunch is the app restart.
14. `finally`: remove the temp root.

Platform notes:

- macOS tools are absolute `/usr/bin` paths; Windows tools (`tar`, `robocopy`, `powershell`) resolve from PATH.
- `robocopy` exit codes 0–7 are success (bitmask); `run()` is bypassed for it — a non-zero code is not a failure. Runs with `/MT:16` (parallel threads) and is only the copy engine when a same-volume rename is impossible.
- Windows junction re-point (`repointJunctions`) runs ONCE after the final install. It walks the installed source with `Dirent.isSymbolicLink()` (junctions report as links, never recursed into), re-reading each target and rewriting only those under the staging root. Each rewrite builds the replacement junction at a temp name first, then unlinks the stale one and renames the replacement over it — a failure to create the replacement leaves the original in place, and either failure aborts the install rather than shipping a dead link. A robocopy-materialized tree carries no junctions, so the walk is a no-op there.
- `run()` on Windows uses `shell: true` (args quoted for cmd.exe via `cmdQuote`): npm/pnpm/uniterra ship as `.cmd` shims that execFile cannot launch directly (`spawn ENOENT`); cmd.exe resolves them via PATHEXT. `.exe` tools (`tar`, `robocopy`, `powershell`) would resolve either way.
- `.app` discovery accepts any `mac-*` dir (host arch chosen by electron-builder `[INFERRED]`); Windows expects `win-unpacked/` with an `.exe` (any name).

## Decisions

| Decision                                                                             | Rationale                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source is the artifact — CI prebuilds it into the asset, the CLI skips the build     | Matches the repo exactly; skips the multi-minute tsc/esbuild on user machines                                                                                                                                                                                                                                                           |
| Asset absent → auto-generated archive fallback                                       | Releases predating the asset keep building from the raw tarball                                                                                                                                                                                                                                                                         |
| Windows ships `win-unpacked/` (`--win --dir`), not NSIS                              | The source is embedded AFTER packaging; an installer image can't carry it                                                                                                                                                                                                                                                               |
| Windows packages unsigned (`signAndEditExecutable: false` in `electron-builder.yml`) | Uniterra ships unsigned; the skip also avoids the winCodeSign 7z symlink-extraction failure without Developer Mode/admin (electron-builder#8149)                                                                                                                                                                                        |
| Windows installs per-user under `%LOCALAPPDATA%\Programs\Uniterra`                   | No elevation needed; mirrors `~/Applications`                                                                                                                                                                                                                                                                                           |
| Start Menu shortcut is best-effort                                                   | A missing shortcut must never fail the install                                                                                                                                                                                                                                                                                          |
| `--source <dir>` local checkout mode + `--move-source` opt-in                        | Windows CI verifies the REAL CLI end-to-end without downloading a release; `--move-source` makes the disposable checkout embed via the same same-volume move a downloaded source gets, so the gate replays the closer-to-real user flow instead of paying for a full-tree robocopy (the `verify-windows-install` 17-min cost, issue #3) |
| `uniterra update` = CLI self-update + full rebuild + relaunch (one command)          | The desktop's Update Now quits and runs exactly this — no separate `uniterra setup` for users                                                                                                                                                                                                                                           |
| `uniterra update` refreshes the CLI FIRST                                            | npm/permission problems fail fast, before the multi-minute build                                                                                                                                                                                                                                                                        |
| `CI=true` injected into pnpm install                                                 | pnpm 11 aborts without a TTY                                                                                                                                                                                                                                                                                                            |
| pnpm self-provisioned via `npx pnpm@<pin>` when absent                               | The CLI runs on node (npm/npx bundled), so pnpm is the only runtime dep that can be missing                                                                                                                                                                                                                                             |
| Subprocess failures surface stderr + exit code                                       | `electron-builder`'s real reason (e.g. a binary download) must never be swallowed                                                                                                                                                                                                                                                       |
| `/releases/latest` 404 → fall back to `releases?per_page=1`                          | `/releases/latest` excludes prereleases; beta tags must still install                                                                                                                                                                                                                                                                   |
| `UNITERRA_GITHUB_REPO` env override                                                  | Point the installer at a fork/mirror in tests                                                                                                                                                                                                                                                                                           |
| Windows junctions re-pointed after the FINAL install (not re-copied or hoisted)      | the same-volume `rename` (embed and install) preserves pnpm's absolute junction targets verbatim, so once the staging tree is deleted every `.pnpm` link is dead — re-point them against the installed source dir (the embed-time path is broken again by the install rename)                                                           |
| Version stamp: release tag without `v`; `--source`: source desktop version           | Align app metadata with the release tag                                                                                                                                                                                                                                                                                                 |

## Dependencies

- Outbound: node builtins (`fs`, `child_process`, `stream`), platform tools (macOS `/usr/bin/*`; Windows `tar`/`robocopy`/`powershell`), GitHub API, npm registry.
- Inbound: none in-repo (leaf package; the desktop does NOT import it).

## Patterns & Gotchas

- macOS subprocesses use absolute `/usr/bin` paths — never rely on PATH there; Windows resolves tools from PATH (`.exe` directly, `.cmd` shims through `shell: true` + PATHEXT).
- PBT (`test/pbt.test.mts`) locks arg parsing (`--source` consumption and the `--move-source`-requires-`--source` rule included), the `installPlan` stage order (`update` = CLI refresh → rebuild → relaunch; `setup` never touches the CLI; dry-run runs nothing), `.app` + `win-unpacked` discovery, install destinations, builder args, shortcut script quoting, the prebuilt-asset selection (matching asset wins at any position, else the auto-archive fallback), the marker→skip-build decision, `embedStrategy` (a downloaded OR explicitly-movable Windows source moves; everything else copies), `commandErrorMessage` (command line + exit code + captured output), pnpm self-provisioning (`pnpm` vs `npx pnpm@<pin>`; unknown pin throws), and `remapJunctionTarget` (staging prefix → embedded prefix with the suffix intact; non-staging targets → `undefined`; `\\?\`/forward-slash/case normalization).
- `prepack` runs `pnpm run build` so npm ships a freshly compiled `dist/`.

## How to Update

- New command/flag → update the Public API table + `parseArgs` PBT.
- Install steps change → update the Setup Flow list, run `scripts/verify-cli-container/run.sh` (Linux container), and re-run `scripts/verify-windows-install/verify.ps1` via the release gate (windows-latest).
